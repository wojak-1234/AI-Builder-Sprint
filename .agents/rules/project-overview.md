# 1. 프로젝트 개요

# Project
서비스명 : 이음

OCR과 AI를 활용한 기억 건강 관리 및 세대 간 회상 지원 플랫폼

목표
- 옛 사진·편지·일기를 OCR/음성으로 디지털화
- AI가 개인화된 회상 질문을 생성해 자기 서사 구축을 돕는다
- 정기적 회상 세션으로 인지 자극·정서적 웰빙을 지원한다 (비약물적 개입, 진단 아님)
- 사용자(어르신)와 보호자(자녀)가 공통 질문을 공유받고 답하며,
  두 사람의 기억이 하나의 공유 마인드맵으로 통합되는 세대 간 연결 경험 제공

핵심 원칙: 이 서비스는 절대 의료적 진단이나 정답 판정을 하지 않으며,
항상 질문형으로 사용자 스스로/가족과 함께 자신을 이해하도록 돕는다.

형태: PWA (웹 우선 출시). 데스크톱 데모 최적화를 우선하되 반응형(모바일 퍼스트
Tailwind 규칙)은 유지한다. 네이티브 앱스토어 배포는 하지 않는다.

# 2. 기술 스택

## Tech Stack
- Next.js (App Router) + next-pwa
- React + TypeScript
- Tailwind CSS (모바일 퍼스트)
- Firebase (Auth, Firestore, Storage, Cloud Messaging)

Next.js API Routes로 전부 처리한다.

# 3. 코딩 스타일

## Coding Style
- TypeScript strict mode
- 함수형 컴포넌트만 사용
- any 사용 금지 (불가피하면 unknown + 타입가드, 이유 주석 필수)
- interface보다 type 선호
- async/await 사용, Promise.then 체이닝 금지
- 모든 외부 API 호출(Upstage, Gemini, Firebase)은 try-catch로 감싼다
- LLM 응답은 반드시 JSON 스키마로 강제하고, 파싱 실패 시 fallback 값을 준비한다

## 모바일 퍼스트 UI 규칙 (반응형 유지용)
- 모든 Tailwind 클래스는 prefix 없는 상태(모바일 기본값)를 먼저 작성하고,
  데스크톱 대응은 sm:/md:/lg: prefix로 "추가"하는 방식으로만 작성한다.
- 패딩/마진 기본값은 모바일 기준 p-3~p-4, gap-2~gap-4를 기본으로 하고,
  sm: 이상에서만 늘린다.
- grid-cols는 기본값 grid-cols-1, sm:grid-cols-2 이상부터 확장한다.
- max-w-* + mx-auto 컨테이너는 모바일 기본값에서 w-full 유지, sm: 이상에서만 max-w 적용.
- 단, 데모 화면(나이테/공유 마인드맵 메인 뷰)은 데스크톱 와이드 레이아웃을
  우선 다듬고, 모바일은 핵심 정보가 세로로 무너지지 않는 선에서만 대응한다.

# 5. UI 규칙

## 흐름 원칙 — 탭바 대신 선형 스택 구조

스플래시/온보딩 → 역할 분기(최초 1회: 본인모드/보호자모드)
→ 홈(오늘의 질문 1개) → 답변화면(텍스트/음성/사진 택1)
→ 완료화면(자동 홈 복귀) → [부가: "내 이야기 보기" 링크로만 진입]

- 하단 탭바를 사용하지 않는다. 부가 기능(서사 보기, 공유 마인드맵)은
  홈 화면 안의 링크로만 노출한다.
- 한 화면 한 행동 원칙: 화면마다 주요 행동은 1개로 제한한다.
- 뒤로가기는 브라우저 기본 동작에 의존하지 않고, 항상 "홈으로" 버튼을 명시한다.
- 로딩 중에는 스피너만 두지 않고 "잘 기록됐어요" 같은 명확한 문구로 상태를 알린다.
- 보호자 화면은 세로 스크롤 한 화면 안에 정보를 몰아 넣고, 새 내비게이션
  패턴을 별도로 만들지 않는다.

## 컴포넌트/스타일 규칙
- 모든 버튼/인풋은 공통 컴포넌트(Button, Input)를 사용, 개별 스타일링 금지
- Tailwind만 사용, inline style 금지
- 어르신 사용성 고려: 기본 폰트 큼직하게, 터치 영역 넓게
- 그래프/마인드맵은 읽기 전용 카드 기반으로만 조작한다.
  드래그, 노드 이동, 연결선 긋기 등 그래프 편집 UI는 절대 만들지 않는다.
  (옵시디언과의 차별화 원칙 + 노년층 조작 부담 최소화를 위함)
- 정보 수정 흐름은 항상 2단계로 끝낸다:
  "맞아요/아니에요/삭제할래요" 버튼 → (틀렸다면) 짧은 텍스트 재입력 필드 하나만

# 7. AI 행동 규칙 ⭐⭐⭐ (이 프로젝트에서 가장 중요)

## 절대 원칙
1. 어떤 경우에도 진단하지 않는다.
   - 금지: "치매 초기 증상 같습니다", "인지저하가 의심됩니다"
   - 허용: "최근 답변에서 같은 단어를 반복하시네요, 요즘 컨디션은 어때요?"
2. 조언·처방을 생성하지 않는다. 모든 출력은 개방형 질문으로 끝난다.
3. 사용자가 제공한 사실만 사용하고, 없는 사실을 지어내지 않는다.
4. 판단은 항상 사용자 본인의 몫으로 남긴다.
5. **정답/오답 판정을 하지 않는다.** 퀴즈·채점 형식을 사용하지 않는다.
   서로 다른 기억은 "결함"이 아니라 "각자의 기억"으로 병기한다.
   점수·정답률·랭킹 등 평가적 지표를 노출하지 않는다.
6. 가족 공유 기능은 사용자의 사전 명시적 동의(opt-in)가 있을 때만 작동하며,
   답변 단위로 개별 비공개 처리가 가능해야 한다.
7. OCR 신뢰도가 낮으면 추측하지 않고 재촬영/재확인을 요청한다.
8. 공유 질문에 한쪽만 답해도 매듭을 생성하며, 다른 쪽의 참여를 강제하지 않는다.

## 일반 개발 원칙
- 새 라이브러리를 추가하기 전에 기존 스택으로 해결 가능한지 먼저 확인한다.
- 필요 없는 의존성은 설치하지 않는다.
- 기존 코드를 최대한 재사용하고, patterns/ 폴더를 먼저 확인한다.
- 4-에이전트 구조를 임의로 바꾸지 않는다.
- 불필요한 리팩토링을 하지 않는다 (6일 스프린트, 시간 여유 없음).
- 새로운 재사용 가능한 해법을 찾으면 patterns/ 에 기록할 것을 제안한다.

# 16. 온보딩 & 사용자 역할 구조

## 역할 분기 (최초 1회)

"어떻게 시작하시겠어요?"
A. 저는 제 이야기를 직접 기록할래요 (본인 모드 — 예방/증진 목적)
B. 가족의 이야기를 대신 기록해드릴래요 (보호자 대리 모드)

- 본인 모드: 사용자가 직접 업로드·답변
- 보호자 모드: 보호자 계정이 환자 계정에 연동되어 대리 입력, 모든 대리 기록에는
  "보호자가 대신 기록함" 출처 태그를 남긴다.
- 두 모드는 배타적이지 않다. 보호자와 사용자가 함께 쓰는 "공유 모드"가 기본 지향점.

## 공유 질문 & 관점 병합
- AI가 curated 질문(빈도 조절 가능)을 사용자와 보호자 양쪽에 동시 발송 가능
- 각자 답변 → narrative-builder가 하나의 매듭(노드)으로 병합
- 일치/차이는 표시하되 "정답/오답"으로 판정하지 않는다 (섹션 7 참조)

# 17. 4-에이전트 구조 (정확히 4개, 늘리지 않음)

## [Agent 1] ocr-extractor
- 입력: Upstage OCR 결과 (사진/편지/일기 스캔본, 손글씨 메모 포함)
- 출력: 구조화된 JSON (인물/장소/날짜/사건)
- 신뢰도 낮으면 재촬영 요청 (추측 금지)

## [Agent 2] question-generator
- 입력: 엔티티 데이터 + 과거 답변 히스토리 + curated 질문 뱅크 + 공유모드 여부
- 출력: 개방형 회상 질문 1~3개
- 공유모드일 경우 동일 질문을 양쪽에 동시 발송하도록 태깅
- 절대 정답을 전제하거나 유도하는 질문을 만들지 않는다

## [Agent 3] narrative-builder
역할이 4단계로 명확히 정의됨:
1. **시간순 정렬**: 답변들을 사건/기록 시점 기준으로 배열
2. **군집화**: 같은 시기·인물·주제의 답변을 묶어 챕터 단위로 구성
3. **자연어 재구성**: 묶인 답변을 매끄러운 문단으로 연결
4. **관점 병합**: 같은 질문/사건에 대한 여러 답변자의 응답을 하나의 노드에
   나란히 배치, 일치/차이를 사실로만 태깅 (판정 아님)

출력은 두 가지:
① 화면 표시용 챕터 요약 (1~2문장, 나이테/마인드맵에 얹힘)
② 전체 서사용 긴 텍스트 ("내 이야기 전체 보기")

부가 역할: 공백/반복 패턴을 감지해 question-generator에 피드백
(공백탐지형/패턴추적형 동적 질문의 재료로 사용)

## [Agent 4] safety-guard
- 입력: Agent 2/3의 출력
- 출력: 통과 또는 재생성 요청
- 검수 항목: 진단성 표현, 조언성 표현, 정답/오답 판정 표현, 사실 왜곡 여부
- 반드시 자동 실행되어야 하며 우회 불가 (hook 또는 명시적 파이프라인 강제 호출)

# 18. 기능 우선순위 (Tier)

## Tier 1 — 반드시 완성
- 일일 저널링 (텍스트 입력, 질문 1개 고정 노출)
- OCR 업로드 → 엔티티 추출 → 질문 생성 → 서사 축적 (본인 모드 기준)
- 나이테 시각화 (읽기 전용)
- safety-guard 검수 파이프라인
- 동적 다음 질문 생성 (최소 1개 유형: 공백탐지형)

## Tier 2 — 시간 되면 추가
- 음성 입력 (Web Speech API)
- 보호자 대리 입력 모드 + 계정 연동
- 공유 질문 + 관점 병합 (narrative-builder 4단계 전체)
- 사진 자동 캡션

## Tier 3 — 로드맵 언급만, 이번 스프린트 구현 안 함
- 얼굴인식, 캘린더 연동
- 복지관/치매안심센터 데이터 연계 대시보드
- 정교한 보호자 전용 편집 화면
